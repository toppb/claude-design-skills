# Narrative Strategies

Five strategic frameworks for landing page wireframe variations. Each defines a distinct narrative
logic — the argument the page makes and the order in which it makes it. Selecting 3–5 strategies
per page produces variations that differ in intent, not just layout.

---

## Strategy 1 — Trust-First

**The argument:** You should trust us before you evaluate us.

**When to use:**
- Enterprise B2B, regulated industries (compliance, security, finance, legal)
- Products where risk perception is high (data handling, critical infrastructure)
- Audiences that are evaluating multiple vendors seriously
- Always include this for Enterprise B2B SaaS

**Narrative logic:**
Lead with credibility signals. Make the visitor feel safe before asking them to understand the product. Every section answers "why trust this company?" before "what does this do?"

**Section sequence:**
1. `Nav` — minimal, professional, no aggressive CTAs
2. `Hero / Split / Content Left` — clear value prop + credibility anchor (e.g. "Trusted by 500+ enterprises")
3. `Logos / Bar / Light` — client logos immediately below the fold
4. `Stats / Band` — proof numbers (customers, uptime, audits passed)
5. `Features / Content Left` — methodology/approach, not features
6. `Testimonials / Grid / 3-col` — named quotes with titles and companies
7. `Features / Icon Grid / 3-col` — capabilities, framed as guarantees
8. `Pricing / 3-tier` OR `CTA / Centered / Light` — only after trust is established
9. `FAQ / Accordion / 1-col` — objection handling
10. `Footer / L`

**Copywriting notes:**
- Eyebrow labels should reference authority: "SOC 2 Type II Certified", "Used by 3 of the top 5 banks"
- Avoid superlatives; use specifics
- CTAs: "Book a demo" or "Talk to sales" — not "Get started free"

## Strategy 2 — Problem-First

**The argument:** You have a painful problem. We solve it.

**When to use:**
- Products addressing a clear, felt pain (compliance burden, manual processes, reporting gaps)
- Audiences who already know they have a problem but haven't found the right solution
- Early-stage awareness campaigns
- Strong fit when the problem is emotionally resonant or costly

**Narrative logic:**
Open by naming the pain. Make the visitor think "yes, that's exactly my problem" before introducing the product. The product appears as the relief to a tension already established.

**Section sequence:**
1. `Nav`
2. `Hero / Centered / Light` OR `Hero / Split` — lead with the problem statement, not the solution
3. `Features / Content Left` — "why existing solutions fail" or "the cost of the status quo"
4. `Stats / Band` — quantify the problem (e.g. "Teams spend 40% of their time on manual compliance tasks")
5. `Features / Icon Grid / 4-col` — introduce the solution capabilities as direct problem answers
6. `Features / Alternating` — deep-dive on the 2–3 most painful use cases solved
7. `Logos / Bar` — "others in your situation chose us"
8. `Testimonials / Grid` — quotes that reference the problem, not just the product
9. `CTA / Centered / Dark` — "Stop doing it the hard way"
10. `Footer`

**Copywriting notes:**
- H1 should name the problem: "Compliance shouldn't take a team of 10"
- Use second-person: "You're spending..." not "Companies are spending..."
- Stats should quantify the pain, not just the product's success
- CTA copy: "See how it works" or "Get the demo" — show, don't sell

## Strategy 3 — Solution-First

**The argument:** Here's exactly what we do and how it works.

**When to use:**
- Audiences with high intent who already know they need this category of product
- Referral traffic (someone told them to check this out)
- Product-led growth, self-serve audiences
- Technical evaluators who want to understand the system before trusting it

**Narrative logic:**
Lead with clarity. Get to the product fast. Show how it works before asking why you should care. Assume the visitor is pre-sold on the category; your job is to demonstrate your specific approach.

**Section sequence:**
1. `Nav` — include login/app link if product exists
2. `Hero / Split` — clear product description + screenshot/UI in hero. No fluff.
3. `Features / Alternating` — step-by-step "how it works" (3 steps with UI shots)
4. `Features / Icon Grid / 4-col` — full capability list
5. `Features / Content Left / Stats` — depth on the most important capability
6. `Logos / Bar` OR `Stats / Band` — quick credibility
7. `Pricing / 3-tier` — surface pricing early for self-serve audiences
8. `Testimonials / Grid / 2-col`
9. `FAQ / Accordion / 2-col` — technical and practical objections
10. `CTA / Banner / Split` — "Start today"
11. `Footer / M`

**Copywriting notes:**
- H1 is a product description, not a tagline: "Continuous compliance monitoring for cloud infrastructure"
- Show the UI early and often — screenshots are copy
- CTAs: "Start free trial" or "Try it yourself" — low friction, self-serve framing

## Strategy 4 — Feature-Dense

**The argument:** We do more than you think. Here's everything.

**When to use:**
- Competitive markets where feature breadth is a differentiator
- Replacing an existing tool (migration/switching audience)
- Power users who evaluate via feature checklists
- Enterprise deals where multiple stakeholders have different feature needs

**Narrative logic:**
Show comprehensiveness. Make the visitor feel that every need they have is covered. This strategy is for visitors who are already evaluating and need to build a case for choosing you over alternatives.

**Section sequence:**
1. `Nav`
2. `Hero / Split` — broad value prop + key differentiator
3. `Features / Icon Grid / 6-col` — quick capability strip (show breadth immediately)
4. `Features / Alternating` — 4–6 capability deep-dives, each with its own use case
5. `Features / Content Left` + `Features / Content Right` — paired sections for related capability clusters
6. `Stats / Cards` — platform scale / reliability numbers
7. `Pricing / Comparison Table` — feature matrix
8. `Logos / Bar`
9. `Testimonials / Grid / 3-col` — quotes from different user personas
10. `FAQ / Accordion / 2-col`
11. `Footer / L`

**Copywriting notes:**
- Each feature section gets its own eyebrow label naming the capability cluster
- Headlines should be specific, not generic: "Evidence collection, automated" not "Powerful integrations"
- Avoid saying "robust", "powerful", "enterprise-grade" — show it, don't label it
- Pricing table should be comprehensive — this audience wants to see the full picture

## Strategy 5 — Conversion-Minimal

**The argument:** Here's the essential case. Act now.

**When to use:**
- High-intent referral or direct traffic (they already know the company)
- Event landing pages, campaign-specific pages
- Short-form pages for a specific offer (free trial, demo, download)
- Retargeting audiences

**Narrative logic:**
Remove friction. Make the page as short as possible while still being credible. Every section that doesn't directly support the conversion is removed. The goal is to get to the CTA as fast as possible.

**Section sequence:**
1. `Nav` — minimal; logo only or logo + single CTA
2. `Hero / Centered / Light` — strong headline + single CTA. No secondary action.
3. `Logos / Bar` — 5–6 logos only, no headline
4. `Features / Icon Grid / 3-col` OR `Stats / Band` — one proof block, not both
5. `Testimonials / Carousel` — single featured quote
6. `CTA / Centered / Dark` — repeat the offer prominently
7. `Footer / S` — copyright + legal only

**Copywriting notes:**
- One CTA label used consistently throughout: pick one of "Get a demo", "Start free", "Book a call" and use it everywhere
- No FAQ — FAQs signal that you expect objections; conversion pages assume the decision is made
- Every headline should reinforce the offer, not introduce new ideas
- Total word count target: 300–500 words for the whole page

## Selection Logic

| Audience | Recommended strategies |
|----------|----------------------|
| Enterprise B2B, first visit | Trust-First + Problem-First + Feature-Dense |
| Technical evaluator, comparison mode | Solution-First + Feature-Dense |
| SMB / prosumer, discovery stage | Problem-First + Solution-First |
| Referral / warm lead | Conversion-Minimal + Solution-First |
| Early-stage awareness | Problem-First + Trust-First |
| Campaign / retargeting | Conversion-Minimal |

**Default for unknown audience:** Trust-First + Problem-First + Solution-First

---

## Using Strategies in Wireframes

1. Select 3–5 strategies based on the brief and audience
2. Each strategy becomes one HTML wireframe variation
3. Label each file with the strategy name: `[project]-[page]-[letter]-[strategy].html`
   - Example: `acme-platform-a-trust-first.html`
4. In the summary notes file, explain what each strategy prioritizes and what it trades off
5. Mark one variation as **Recommended** with a brief rationale
6. The recommended variation should reflect your read of the most likely visitor mindset — not necessarily the longest or most comprehensive page
